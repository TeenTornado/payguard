# ADR-002: No LLM for deterministic checks

**Status:** Accepted  
**Date:** 2026-08-21

## Context

Some checks are fully deterministic: HMAC signature math, key prefix validation (`rzp_test_`), paise arithmetic, HTTP header presence. Using an LLM for these adds latency, cost, and unpredictability where there is a correct answer.

## Decision

The following checks are implemented entirely in deterministic code (static rules, AST analysis, regex) without any LLM involvement:

- Razorpay key prefix validation
- HMAC signature verification correctness
- Amount unit detection (rupees vs paise via AST dataflow)
- Float arithmetic detection on money variables
- HTTP header presence (`X-Razorpay-Signature`)

The LLM is used only for semantic reasoning where code intent is ambiguous: understanding what a variable represents, whether a lookup constitutes a dedup guard, etc.

## Consequences

- Static rules run fast and cheaply, provide rule IDs for evidence, and are fully unit-testable.
- The LLM's role is to reason about intent — not to perform arithmetic or check strings.
- False positives from static rules can be suppressed by the LLM in the normalize step.
