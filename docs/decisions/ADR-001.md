# ADR-001: Verifier is the sole arbiter of money-safety claims

**Status:** Accepted  
**Date:** 2026-08-21

## Context

PayGuard makes claims about whether a payment-integration defect will cause real money loss. Those claims need to be credible to judges, engineers, and anyone reading the report. LLM outputs are probabilistic and can hallucinate. Static analysis can have false positives.

## Decision

A finding may only carry the label **VERIFIED** — and may only show `exposure_measured_paise` — if the verifier has successfully executed the defect scenario against the sandbox and observed the documented pass condition. No other code path may write `status=VERIFIED` or set `exposure_measured_paise`.

LLM-only and static-only findings are labeled **"AI finding — unverified"** in the UI until verified.

## Consequences

- VERIFIED is a strong signal. Judges can trust it.
- Some findings will remain ADVISORY or UNVERIFIED because they are not runnable (manifest missing, routing unavailable). These are still reported, but labeled accurately.
- The verifier infrastructure is the most complex part of the system, and must be built before any evaluation numbers are reported.
