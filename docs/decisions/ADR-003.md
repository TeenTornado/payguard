# ADR-003: Test mode mandatory, enforced by key prefix at two layers

**Status:** Accepted  
**Date:** 2026-08-21

## Context

The buildathon requirement is strict: no live payment processing. A misconfigured key or a code path that bypasses the check could trigger real charges.

## Decision

Test mode is enforced at two independent layers:

1. **Config load** (`payguard/shared/config.py`): `Settings.razorpay_test_key_id` has a `@field_validator` that raises `ValueError` if the key does not start with `rzp_test_`. `PAYGUARD_ENV` must equal `TEST` or the settings object raises. The settings object is constructed at startup via `@lru_cache`.

2. **Gateway layer** (`payguard/gateway/`): Every credential passed to the gateway is checked with `validate_key_prefix()` before any Razorpay API call (real or emulated). A credential not starting with `rzp_test_` results in an HTTP 403 with reason `LIVE_KEY_REJECTED`.

3. **Unit test** (`tests/unit/test_config.py`): asserts that both layers reject a live key, and that a non-TEST `PAYGUARD_ENV` raises at settings construction.

## Consequences

- No live code path exists. The checks are structural, not advisory.
- FORWARD_TEST mode (real Razorpay API) only works with `rzp_test_` credentials — which are Razorpay's test environment, not live.
- The unit test is a non-negotiable; it must never be xfailed or deleted.
