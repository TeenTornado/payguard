# ADR-005: Remediation requires human approval, never auto-merges

**Status:** Accepted  
**Date:** 2026-08-21

## Context

Auto-applying AI-generated patches to payment code is exactly the class of risk PayGuard is designed to detect. Doing it ourselves would undermine the project's thesis and be genuinely unsafe.

## Decision

Remediation flow:
1. System proposes a diff (`Remediation.status = PROPOSED`).
2. The diff is displayed in the UI with a full before/after view and a rationale.
3. A human clicks Approve or Reject — this is audited with `HUMAN_APPROVED` or `HUMAN_REJECTED`.
4. Approved remediations are displayed as a patch to apply manually; they are never applied by the system.
5. After a human applies a patch, they may trigger re-verification (also requires explicit click).

No code path in PayGuard writes to or modifies the target repository.

## Consequences

- The system is safe to run on production codebases without risk of unwanted changes.
- The remediation feature is primarily a code-review aid, not an auto-fixer.
- The stretch goal (closed-loop re-verify) requires: propose → human apply → human trigger re-verify.
