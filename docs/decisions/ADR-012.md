# ADR-012: The retrieval corpus is split-safe (TRAIN examples only)

**Status:** Accepted
**Date:** 2026-08-24

## Context

We measure the grounded analyzer (System C+RAG) against the baseline (System C) on the SAME frozen
val/test splits. The grounding KB's EXAMPLE tier is built from the labeled dataset. If we indexed
val or test samples, the retriever could hand the analyzer a near-copy — or the exact snippet — of
the sample it is judging during evaluation. The reported precision/recall would then reflect
memorization through retrieval, not generalization, and the C-vs-C+RAG comparison would be
meaningless.

## Decision

The EXAMPLE tier is built from the **TRAIN split only**. Val and test samples are never indexed.
This is enforced two ways:

1. By construction: `example_chunks_from_train()` iterates the splitter's `train` set only.
2. By test: `tests/unit/test_kb_leakage.py` asserts that NONE of the val/test `sample_id`s (from
   the deterministic splitter and the frozen `test.manifest.json`) appear in the built index's
   chunk metadata. CI-enforced.

The RULE tier is hand-curated documentation, not dataset samples, so it carries no split.

## Consequences

- The C-vs-C+RAG numbers are honest: any gain comes from generalizable grounding, not leaked
  test snippets.
- The retriever cannot "cheat" by retrieving the sample under evaluation.
- Adding new samples requires re-running `make kb-index`; the leakage test guards every rebuild.
