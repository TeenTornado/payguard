# ADR-004: Repository-level splits prevent label leakage

**Status:** Accepted  
**Date:** 2026-08-21

## Context

If samples from the same repository (same code lineage) appear in both train and test, the model may memorize patterns rather than generalize. Evaluation numbers would be artificially inflated.

## Decision

The dataset is split by `repo_id` (not by sample), with a fixed random seed. All samples with the same `repo_id` go into exactly one of train/val/test. The split is 60/20/20.

`dataset/splits/test.manifest.json` is frozen on creation: it stores sample IDs and their content hashes. `make eval` validates hashes before running, and aborts if any test sample has been modified.

Rules, prompts, and thresholds are developed against train/val only. Running `make eval` appends to `eval/reports/ledger.jsonl` — every run is recorded and the ledger is committed.

## Consequences

- Evaluation numbers are honest.
- The ledger shows all test-split evaluation runs, including bad ones. Cherry-picking is prevented by commitment.
- Adding new samples to the dataset requires re-splitting, which may change val numbers — this is expected and fine.
